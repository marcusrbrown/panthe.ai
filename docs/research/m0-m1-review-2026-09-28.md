# M0/M1 review and OpenCode implementation prompt

Review date: 2026-09-28. Baseline: `15e7f98`.
This is a review and proposed follow-up, not a new owner decision or a change to milestone status.

## Assessment

The implementation follows the original architecture well. The pure world engine, SQLite transactions, separate Bun service, Tauri lifecycle supervisor, and client rendering of committed state form a coherent foundation. Durable proposal acceptance, atomic tick recording, staged world imports, and explicit presentation receipts are valuable improvements over the initial high-level recommendation. The scenario harness tests consequences across these boundaries, including process failure, instead of relying only on isolated package tests.

M0 usefully revised the initial assumptions. D25's measured WebGL2 fallback preserves the chosen stack on the actual Mac. QuickJS with an external supervisor is a researched implementation of the requested restricted runtime; Lua was an option, not an owner mandate. The measured smaller local model is a sensible starting profile, but schema validity and action-kind scores do not yet establish convincing characters. The corrected image/inference measurements also show that continuous activity on 16 GB remains a real scheduling problem.

M1 establishes a persistent rules-driven world, not yet the autonomous social simulation described in the interview. `packages/agents`, `packages/behaviors`, and `packages/assets` still expose `ready: false` placeholders. That is consistent with the milestone sequence. The largest remaining product risk is whether limited local inference produces distinct, responsive gods whose experiences change their relationships and actions. More infrastructure alone will not resolve it.

## Prompt to give OpenCode

Review the findings below against the current branch, then use Systematic's plan → work → review → compound workflow. Read `AGENTS.md`, the product reading order, ADR-0008, and the greenfield anti-overengineering solution first. Preserve the accepted M0/M1 architecture and owner decisions. Make small, evidence-backed corrections before extending the M2 agent loop; then deliver M2 through a causal scenario. Do not turn this review into a framework rewrite or silently expand the MVP.

### 1. Fix three correctness gaps before agents depend on them

**A. An event reference does not verify a legend's assertion — W05, W07.**

Evidence: `packages/world/src/validate.ts`, `handleLegend` (around line 511), sets `verified` whenever `linkedEventId` exists. `apps/simulation/src/tick.ts`, `checkLegendIntake` (around line 463), checks only that the event exists. The existing intake test even links a claim about a tavern burning to an actor-movement event.

Reproduction: commit the farmer's move to the tavern, then submit a legend asserting “Zeus destroyed the entire Underworld” with that movement event's ID. Intake succeeds and validation emits `legend-recorded` with `verified: true`.

Keep free-form, possibly false stories. Separate an attributed assertion and its evidence links from authoritative facts. An existing link may be labeled “event-linked”; it must not certify arbitrary prose as true. Do not add an LLM truth judge. Test unrelated links, genuine links, absent links, and unknown IDs, and update all consumers of the current flag consistently.

**B. Observation IDs can silently refer to conflicting evidence — W04, O04.**

Evidence: `packages/telemetry/src/trace.ts:93` uses `INSERT OR IGNORE`; its test explicitly records different facts under the same ID and expects the first record to win. External intake checks proposal/observation ID equality, but neither that check nor journal idempotency prevents a different proposal ID from carrying different content for an existing observation ID.

Reproduction: commit a farmer move with observation A; commit a second valid move under a new proposal ID while reusing A's ID with different facts and state revision. Both actions commit, but the second action's trace resolves the first observation's facts.

Make an observation identity immutable. Exact reuse may be valid; conflicting reuse must yield an explicit outcome without poisoning the tick or overwriting history. Cover two pending proposals, a previously recorded observation, and restart. Preserve legitimate multiple proposals from the same unchanged observation. Have the trusted service build model observations; do not let model output invent its own evidence or select another actor's observation. Keep operator/fixture provenance explicit.

**C. Desktop frame deduplication omits visible state — W03, O03, X04.**

Evidence: `apps/desktop/src-tauri/src/state.rs:25` and `proxy.rs:34` key frames only by event sequence, status, and session. The sidecar's frame also contains tick-dependent state, recent-event windows, degraded reason, and catch-up summary. The UI displays tick and degraded reason. `proxy.rs` already detects a changed degraded reason for the tray, but that change alone does not forward a frame to the webview.

Make the frame change criterion cover observable changes. Test an eventless advancing tick, a changed degraded reason with unchanged status, and a summary-only update, while retaining stale-launch rejection and resubscription replay. Keep ADR-0008's one-second full-state polling unless measurements justify a separate transport decision; this finding does not require WebSockets or delta synchronization.

### 2. Extend causal history where M2 memory needs it

Requirements: W04, W08–W09, O01, O04.

`packages/telemetry/src/query.ts` explicitly stops environmental causality at the automatic tick: destruction is not linked back to the strike that ignited the fire. Archives also omit traces, as the roadmap already acknowledges. These are documented limits, but they become consequential when memories, blame, grudges, and experiment comparisons depend on history.

Carry the relevant committed cause through ignition, spread, and destruction. Keep objective causation separate from what a witness believes: an unseen instigator must not become known merely because the inspector can find it. Connect model request, validated proposal, outcome, and relationship change without exposing private observations across characters.

Decide which causal records must survive a branch/restore and preserve them when the first persisted agent memories depend on them. Full trace-retention policy and dashboards can remain M6 work. Do not fabricate missing pre-restore traces. Also assign the known catch-up-summary delivery loss a concrete follow-up gate; a committed backlog and a client receiving its summary are different facts.

Acceptance: inspect “why was the tavern destroyed?” through its actual initiating event; contrast a witness's account with an uninformed character's belief; restore the world and retain the evidence required to explain its persisted relationship changes.

### 3. Make M2 prove the original experience

Requirements: W01, W04, W06, W09–W10, P06–P07, O04, O08.

Build one vertical slice first: a god's observable action changes the town; a witness remembers it; another character receives an imperfect report; their relationship and next choice change. Include distinct sourced drives for Zeus and another god, then expand through the same contracts to all seven. Attribute director interventions separately. A model-generated explanation is an in-character account, not a guaranteed transcript of its internal reasoning.

Use trusted perception-derived contexts rather than the full observer frame. Cover a private event that stays unknown, a legitimate report/divine-sense path, a false belief, and durable memory after restart. Validate delayed model proposals against current authority after the world changes. No inference call should hold a world transaction open or stop routine ticks.

The probe's approximately 39 turns/minute is a capacity estimate, not a demonstrated live scheduler. Implement the gods-first/routine-supported policy with explicit fairness, bounded pending work, stale-result handling, and priority for direct interaction. Ordinary inhabitants must retain their action capabilities and become responsive when involved; they must not become permanent scenery. Measure queue wait separately from generation time and time to committed/presented consequence. Renderer FPS does not establish conversational or future player-input latency.

Promote reusable provider/repair code from probes into production packages without making production import probe tooling. Test the actual production routing path for configured fallback and offline silence. Keep OpenAI/Anthropic live support labeled unverified until exercised; fixture support is different evidence.

Evaluate more than JSON validity: valid target/action, perception compliance, recognizable drives, repeated behavior, consequential relationship changes, and owner-rated story interest. Add an unattended run with a provider outage and recovery on the M1 Pro. Preserve the seven-god scope; use measured scheduling and context choices to fit it.

### 4. Close the resource-policy ambiguity without blocking all M2 work

Requirements: P04, U06–U07, O08.

The corrected comparable pair shows LLM p95 increasing from 1242 to 3086 ms while six images complete under the 3 GiB policy. It does not support that policy. Other candidates lack a comparable baseline. ADR-0005's Decision says no verdict can be assigned to those candidates, while its historical Consequences text and the roadmap still say the mutex/unconstrained candidates remain rejected.

Reconcile those statements and give the unresolved coexistence work an explicit next gate now that M1 is closed. Run comparable candidates against the emerging M2 workload before accepting concurrent image generation in M4. Record errors, successes, queue wait, completed images, responsiveness, and memory together. Keep continuous character activity ahead of final artwork, using the already accepted temporary/procedural art path. Do not silently drop offline image generation or claim a winning policy from noncomparable runs.

### 5. Keep architecture and documentation proportional to the work

Retain the pure world reducer, injected persistence composition, atomic event/clock/PRNG/trace writes, durable journal, and read-only renderer. Keep the tick's transaction boundary visible. Add perception, memory, and scheduling responsibilities in `packages/agents`; keep HTTP handling in the service adapter. Extract code when a concrete new responsibility warrants it, not to satisfy an arbitrary file-length limit. Avoid a generic actor/plugin framework, premature migrations, or multiplayer authorization design.

Refresh the current-state pointers in `docs/README.md` and the architecture recommendation so a new agent can distinguish the original proposal from accepted ADRs. ADR-0008 says database schema 3 while `packages/persistence/src/store.ts` declares 4. Preserve historical assessments and superseded decisions, but link them to the current authority. Keep partial requirement statuses honest and attach new evidence in `traceability.md`.

The polished art, complete onboarding, playable afterlife, generated behavior integration, replay UI, and Windows/Linux builds remain later milestone work. Their absence alone is not a reason to reopen M1. Likewise, documented packaged/sleep/wake/restore limits must remain visible without being described as independently verified by this review.

### Delivery and validation

Start with a focused regression-fix plan for item 1. Separate it from the M2 plan, which should identify the causal-history dependencies and the resource-policy gate. Every change needs a concrete failing case and passing evidence tied to requirement IDs. Re-run the required Bun/Rust checks and the compiled M1 scenario after relevant changes. Add packaged evidence where the change concerns the shell/view, and real local inference evidence where it concerns agents. Capture reusable lessons in `docs/solutions/`. Report remaining uncertainty rather than filling it with additional abstractions.
