# Stack research: rendering, desktop, backend, sandbox

Reviewed 2026-09-26 from linked documentation. Documentation review, not hands-on tests, except where the probe link says otherwise.

## Bottom line

WebKit gates `navigator.gpu` to macOS 26. The embedded WKWebView on macOS 15.7 does not expose WebGPU; the empirical probe in [tools/probes/webgpu-wkwebview](../../tools/probes/webgpu-wkwebview/README.md) confirms it, including after forcing the private `WebGPUEnabled` feature flag. Owner resolution: dual backend, WebGL2 baseline (see [ADR-0002](../decisions/0002-renderer-backend.md)).

## Three Flatland

- Package `three-flatland`, repo `thejustinwalsh/three-flatland`. Latest `0.1.0-alpha.10` (npm `latest`). Alpha: expect breaking changes; irregular release cadence. <https://www.npmjs.com/package/three-flatland>
- README states `three ^0.185.1`; docs prompt says `>= 0.183.1`. Use the published `package.json` peer range as authority.
- WebGPU-native, TSL materials, requires `WebGPURenderer` from `three/webgpu` and `await renderer.init()`. README claims materials compile for WebGPU or WebGL 2 depending on renderer; not proof every effect works on WebGL 2.
- Documented primitives: `layer` + `zIndex` ordering (not a full isometric depth sort), `AnimatedSprite2D`, tilemaps, TSL effects, hit testing. Particle/lightning/fire availability in alpha.10 unverified.
- Imports: `three-flatland`, `three-flatland/react`, `@three-flatland/nodes`. Docs warn against `WebGLRenderer` and omitting `renderer.init()`.
- Machine-readable docs (`llms.txt`, `llms-full.txt` at thejustinwalsh.com / tjw.dev) did not fetch during review; still unverified. <https://tjw.dev/three-flatland/llm-prompts/>

## Three.js

- `three@0.186.0` (r186). `import { WebGPURenderer } from 'three/webgpu'`; TSL from `three/tsl`. WebGPU default backend, WebGL 2 fallback; async init. <https://threejs.org/manual/pages/webgpurenderer>

## Tauri v2

- Core `2.11.5` (2026-07-01); CLI `2.11.4`; JS API `2.11.1`. Pin separately. <https://v2.tauri.app/release/>
- macOS: WKWebView (system WebKit). WebGPU requires macOS 26 per WebKit notes. No Tauri option to enable it on older OS. <https://tauri.app/reference/webview-versions/>
- Windows: WebView2 (Chromium, self-updating). WebGPU depends on installed runtime + GPU path; validate on packaged app.
- Linux: WebKitGTK 2.54; WebGPU not established. Treat as unsupported until `navigator.gpu` is demonstrated.

## Sidecar and Bun

- `bundle.externalBin` with one binary per target triple (`name-aarch64-apple-darwin`, `.exe` on Windows). `Command.sidecar()` from `@tauri-apps/plugin-shell`; needs `shell:allow-execute`/`allow-spawn`. <https://v2.tauri.app/develop/sidecar/>
- Bun `1.4.2`. `bun build --compile --target` supports macOS arm64/x64, Windows x64/arm64, Linux x64/arm64 glibc/musl. Executables embed the runtime (large). Signing/notarization of a Bun sidecar inside a Tauri bundle: unverified. <https://bun.sh/docs/bundler/executables>
- Sidecar lifecycle: no documented auto-kill on window close or auto-detach. Track the child handle; explicit shutdown. A service that outlives the app needs its own supervision.
- `bun:sqlite` built-in synchronous driver; transactions, prepared statements. <https://bun.sh/docs/runtime/sqlite>
- Workspaces via `package.json`; `bun test` built in.

## HUD framework

No strong signal. Flatland provides a React Three Fiber integration; its guidance says DOM overlay UI should use the DOM, not the Flatland renderer. Keep canvas and overlay loosely coupled.

## Sandboxed generated behavior

| Option | Version | Limits |
| --- | --- | --- |
| wasmoon (Lua 5.4 WASM) | 1.16.0 | No documented instruction budget or hard memory limit; host bindings are the boundary |
| fengari (Lua 5.3 JS) | 0.1.5 | No documented limit hooks; relies on JS GC |
| quickjs-emscripten-core | 0.32.0 | `setInterruptHandler`, `setMemoryLimit`, `setMaxStackSize`, custom module loader; README lists Bun |
| Boa (Rust) | experimental | Requires Rust boundary; no established limit hooks |

Recommendation: QuickJS has the clearest documented controls; Lua remains an option if the behavior language must be Lua. Process isolation plus API validation is the real boundary regardless of interpreter.
